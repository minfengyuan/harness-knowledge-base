# AGENTS.md for GPT-6 Astra

Treat every applicable `AGENTS.md` as always-on context for its directory scope. Inspect parent, nested, and override files that can affect the target before revising a rule.

## Keep

- Stable repository facts and conventions that cannot be inferred cheaply.
- Concrete scope, compatibility, security, credential, production, and destructive-action boundaries.
- Contextual routes to architecture, schema, deployment, or subsystem guidance.
- Project-specific commands or test properties that change safe execution.
- Completion expectations when Astra might otherwise stop before the requested outcome is fully verified.

## Simplify

- Replace unconditional repository maps or mandatory document stacks with routes tied to a task, directory, artifact, or risk.
- Replace blanket test, search, review, and delegation rituals with proportional criteria unless the repository has a concrete mandatory gate.
- Remove duplicated platform behavior, generic coding advice, obsolete model workarounds, and rules repeated at several instruction levels.
- Recast broad stop-and-ask rules around the material decision, authority boundary, or risk that actually requires user input.
- Consolidate shared rules at the highest valid scope. Keep nested files for genuine local refinements and state an override explicitly when precedence would otherwise be ambiguous.

## Shared-model compatibility

If the file governs several models, preserve guidance still required by those models. Prefer model-neutral project facts and risk boundaries. Put Astra-only persistence or autonomy guidance in an Astra-specific layer when a shared rule would harm another supported model.

## Validation

Check the final effective chain for contradictions, hidden mandatory rules, broken routes, and unnecessary repeated context. Exercise a small task, a subsystem-specific task, and a consequential task mentally or with available evaluation tooling; each should load only the guidance it needs and retain the correct permission boundary.
